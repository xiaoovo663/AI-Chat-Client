# AI Chat Client

> 一个单文件、零后端、开箱即用的纯前端 AI 对话客户端。

[在线体验](https://ai-ol.pages.dev) · [开源仓库](https://github.com/xiaoovo663/AI-Chat-Client) · [MIT License](https://github.com/xiaoovo663/AI-Chat-Client/blob/main/LICENSE)

---

## 📌 项目简介

AI Chat Client 是一个面向个人用户的轻量级 AI 对话客户端。它的核心目标是：

- **无需安装**：不需要 Node.js、npm、构建工具或后端服务；
- **无需部署后端**：所有请求由浏览器直接发送到你配置的 OpenAI 兼容接口；
- **双击即用**：下载 `index.html` 后，用浏览器打开即可开始对话；
- **数据本地化**：API 配置与聊天记录保存在浏览器 `localStorage`，不上传到本项目服务器；
- **广泛兼容**：支持所有遵循 OpenAI API 规范的服务，包括云端 API 与本地模型。

项目采用 MIT License 开源，可自由使用、修改与分发。

> **版本说明**  
> 在线体验版已包含作者完成适配、但尚未同步到开源仓库的增强功能；本仓库当前提供稳定开源版。  
> 两个版本的功能差异见「版本与开源说明」。在线版功能以实际页面为准。

## ✨ 项目特性

### 基础能力

- **单文件分发**：核心仅一个 `index.html`，无需构建，下载后双击即可运行。
- **OpenAI 接口兼容**：支持所有遵循 OpenAI API 规范的服务，包括 OpenAI、DeepSeek、Moonshot、通义千问、One API、New API、本地 Ollama 等。
- **流式输出**：支持 SSE 流式回复，呈现打字机效果，减少等待感。
- **多模态图片上传**：支持图片上传与自动压缩，需搭配支持视觉能力的模型使用。
- **模型列表获取**：配置 API 后可尝试一键获取服务商提供的模型列表。
- **参数调节**：支持 `temperature`、`top_p` 等常用生成参数调节。
- **响应式界面**：基于 Tailwind CSS 构建，适配桌面、平板与移动端。
- **本地数据存储**：API 配置与聊天记录保存在浏览器 `localStorage`。
- **无后端依赖**：不收集、不存储用户对话内容，不经过本项目服务器。
- **MIT 开源**：可自由使用、修改与分发。

### 在线体验版增强能力

以下能力已在线体验版提供，源码正在逐步同步到开源仓库：

- 多会话管理
- 对话导出
- 深色主题
- Markdown 渲染增强
- PWA / 离线启动
- 多 LLM Profile
- 上下文裁剪 / 长对话优化

具体可用性以在线体验版实际页面为准。

## 🌐 在线体验与本地使用

### 在线体验

直接访问：

**https://ai-ol.pages.dev**

无需安装。打开页面后，进入设置，填写 API Base URL、API Key 与模型名称即可开始对话。

> 在线体验版用于优先验证增强功能，可能领先于开源仓库。请勿在公共设备上保存长期使用的 API Key。

### 本地使用开源版

1. 下载或克隆本仓库：

   ```bash
   git clone https://github.com/xiaoovo663/AI-Chat-Client.git
   ```

2. 进入项目目录：

   ```bash
   cd AI-Chat-Client
   ```

3. 双击打开 `index.html`，或使用浏览器打开该文件；

4. 在页面设置中填写：

   - API Base URL
   - API Key
   - 模型名称

5. 保存配置后即可开始对话。

> 注意：开源仓库当前为稳定版，可能不包含在线体验版中的部分增强功能。  
> 部分服务商存在 CORS 限制，直接本地打开 `index.html` 可能无法请求 API。可尝试部署到静态托管平台、使用支持跨域的服务商，或自建代理。

## 🚀 快速开始

### 第一步：准备 API

你需要一个兼容 OpenAI 接口的服务。可以是：

- OpenAI 官方 API
- DeepSeek API
- Moonshot / 通义千问等兼容接口
- One API / New API 聚合网关
- 本地 Ollama
- 其他遵循 OpenAI 规范的推理服务

### 第二步：填写配置

打开页面后进入设置，填写以下信息：

| 配置项 | 是否必填 | 说明 | 示例 |
| --- | :---: | --- | --- |
| API Base URL | 是 | OpenAI 兼容接口地址 | `https://api.openai.com/v1` |
| API Key | 通常是 | 服务商提供的密钥；本地 Ollama 可留空或填任意值 | `sk-...` |
| 模型名称 | 是 | 要调用的模型 ID | `gpt-4o-mini`、`deepseek-chat`、`qwen-plus` |
| temperature | 否 | 生成随机性，通常 0–2 | `0.7` |
| top_p | 否 | 核采样参数，通常 0–1 | `1` |

### 第三步：开始对话

保存配置后，在输入框输入问题并发送。若服务商支持流式输出，回复将以打字机效果逐步显示。

### 第四步：按需调整

- 若回复过于发散，降低 `temperature`；
- 若需要更稳定的输出，降低 `top_p`；
- 若需要图片理解，切换到支持视觉能力的模型；
- 若模型列表获取失败，可手动填写模型名称。

## ⚙️ 配置说明

### API Base URL

API Base URL 是服务商的 OpenAI 兼容接口根地址。常见形式：

- 官方 OpenAI：`https://api.openai.com/v1`
- DeepSeek：`https://api.deepseek.com`
- Ollama 本地：`http://localhost:11434/v1`
- One API / New API：你部署的兼容接口地址，通常以 `/v1` 结尾

> 不同服务商对路径要求不同。若请求失败，请先确认是否需要包含 `/v1`，以及服务商文档中的完整 Base URL。

### API Key

API Key 用于鉴权。请注意：

- 不要将真实 Key 提交到仓库、截图或公开分享；
- 本地 Ollama 通常不需要 Key，可留空或填写任意占位值；
- 若使用聚合网关，Key 由网关签发；
- 在公共电脑使用后，请及时清除浏览器数据。

### 模型名称

模型名称必须是服务商支持的模型 ID。例如：

- `gpt-4o-mini`
- `deepseek-chat`
- `qwen-plus`
- `llama3.1`
- `moonshot-v1-8k`

若服务商开放 `/models` 接口，可尝试一键获取模型列表；若获取失败，手动填写即可。

### 生成参数

| 参数 | 作用 | 建议 |
| --- | --- | --- |
| `temperature` | 控制随机性 | 创意写作可高一些，代码/事实问答可低一些 |
| `top_p` | 控制采样范围 | 通常保持默认，或与 temperature 二选一调节 |

> 不同服务商对参数支持程度不同，部分模型可能忽略某些参数。

## 🧩 功能说明

### 流式输出

流式输出通过 SSE 逐步接收模型回复，减少等待感。若服务商不支持流式，或网络环境不稳定，可能会回退为一次性返回。

### 图片上传

图片上传支持多模态对话，但需要：

1. 选择支持视觉能力的模型；
2. 服务商接口支持图片输入；
3. 图片经过自动压缩后仍满足模型要求。

> 图片会上传到你所配置的 API 服务商，不会上传到本项目服务器。请勿上传敏感图片。

### 模型列表获取

部分服务商开放 `/models` 接口，可一键获取模型列表。若获取失败，可能是：

- 服务商未开放该接口；
- Key 权限不足；
- CORS 限制；
- Base URL 路径不正确。

此时手动填写模型名称即可。

### 参数调节

`temperature` 与 `top_p` 会影响生成结果。建议一次只调节一个参数，便于观察效果。

### 本地存储

API 配置与聊天记录保存在浏览器 `localStorage`。这意味着：

- 清除浏览器数据后配置与记录会丢失；
- 不同浏览器、不同设备之间不会自动同步；
- 无痕模式下数据可能在关闭窗口后清除；
- 请不要在公共设备上保存长期使用的 API Key。

## 🛡️ 隐私与安全

### 数据存储

- API Key 与聊天记录仅保存在当前浏览器的 `localStorage`；
- 本项目没有后端，不收集、不存储用户对话内容；
- 对话请求由浏览器直接发送到你配置的 API 服务商；
- 图片会上传到你所配置的 API 服务商，不会上传到本项目服务器。

### 使用建议

- 不要在公共电脑上保存长期使用的 API Key；
- 使用后及时清除浏览器数据或手动删除本地配置；
- 不要将 API Key 提交到仓库、截图或公开分享；
- 不要上传包含个人隐私、密钥、证件等敏感信息的图片或文本；
- 使用第三方 API 时，请遵守对应服务商的条款与计费规则。

### 安全底线

AI 输出属于不可信内容。若项目支持 Markdown 渲染，应做好转义与清洗，避免 XSS 风险。建议：

- 渲染前对 HTML 做转义；
- 使用成熟的清洗库或严格的白名单策略；
- 不直接执行 AI 输出中的脚本、链接或内联事件；
- 对外部链接增加安全属性。

## 🛠️ 技术栈与项目结构

### 技术栈

- HTML5
- 原生 JavaScript
- Tailwind CSS（CDN）
- 浏览器 `localStorage`
- Fetch API / SSE
- 无后端、无数据库、无服务端依赖

### 项目结构

基础开源版核心结构非常简洁：

```text
AI-Chat-Client/
├── index.html      # 核心单文件应用
├── README.md       # 项目说明
├── LICENSE         # MIT License
└── docs/           # 可选文档目录
```

在线增强版可能包含额外静态资源（如 PWA 相关文件），具体以实际部署为准。

### 设计取舍

- **单文件优先**：降低使用门槛，方便下载、分享与静态部署；
- **零后端**：避免服务器成本与数据托管风险；
- **本地存储**：保护隐私，但牺牲跨设备同步；
- **CDN 引入样式**：减少文件体积，但依赖网络加载 Tailwind CSS；
- **功能渐进增强**：基础版保持稳定，增强功能先在线验证。

## 📝 使用建议与已知限制

### 使用建议

- 为不同服务商使用不同的 API Key，便于管理与吊销；
- 定期检查 API 服务商的用量与计费；
- 长对话时注意上下文长度与 token 成本；
- 需要稳定输出时降低 `temperature`；
- 需要图片理解时切换到视觉模型；
- 在公共设备上使用后及时清除本地数据。

### 已知限制

- 部分服务商存在 CORS 限制，直接本地打开 `index.html` 可能无法请求 API；
- 模型列表获取依赖服务商是否开放 `/models` 接口；
- 图片上传依赖模型与服务商的视觉能力；
- 聊天记录仅保存在当前浏览器，不跨设备同步；
- 开源稳定版暂不包含在线体验版的增强功能；
- Tailwind CSS 通过 CDN 引入，首次加载需要网络；
- 单文件架构在功能增多后会增加维护难度，后续会考虑“开发多文件、发布单文件”的轻量构建方式。

## ❓ FAQ

### Q1：为什么在线版功能比开源仓库多？

增强功能会先在在线版验证，稳定后逐步同步到开源仓库。开源仓库当前以稳定单文件版为主。

### Q2：本地打开 `index.html` 无法请求 API？

部分服务商存在 CORS 限制。可尝试：

- 使用支持跨域的服务商；
- 部署到静态托管平台后访问；
- 自建代理；
- 检查 API Base URL 是否包含正确的 `/v1` 路径；
- 检查 Ollama 等本地服务的 CORS 配置。

### Q3：聊天记录存在哪里？

保存在当前浏览器的 `localStorage`。清除浏览器数据后记录会丢失，且不会跨设备同步。

### Q4：API Key 会上传到服务器吗？

不会。本项目无后端，Key 仅保存在本地浏览器中。对话请求由浏览器直接发送到你配置的 API 服务商。

### Q5：如何切换不同服务商？

修改 API Base URL、API Key 与模型名称即可。在线体验版支持多 LLM Profile，开源版同步中。

### Q6：为什么获取模型列表失败？

可能是服务商未开放 `/models` 接口、Key 权限不足、CORS 限制或 Base URL 路径不正确。手动填写模型名称即可。

### Q7：图片上传失败怎么办？

请确认：

- 当前模型支持视觉输入；
- 服务商接口支持图片消息；
- 图片大小与格式符合要求；
- 网络与 CORS 正常。

### Q8：在线版和开源版的数据互通吗？

不互通。两者使用各自浏览器的 `localStorage`，且不同域名下的本地存储相互隔离。

### Q9：可以商用吗？

项目基于 MIT License，可自由使用、修改与分发。但使用第三方 API 时请遵守对应服务商的条款与计费规则。

### Q10：如何清除本地数据？

可在浏览器设置中清除该站点的存储数据，或在页面设置中删除配置与聊天记录。
